# Change Request: CR-001
**Title:** Display Exact Cancellation Cutoff Timestamp and Countdown on Registrations  
**Origin:** Usability Finding OBS-03 (Prototype Validation with External Students)  
**Date:** 2026-11-21 · **Status:** Approved · **Target Version:** SRS v1.1

---

## 1. Description of Change
The current specification (`FR-05` and `FR-06`) dictates that cancellations must occur at least 24 hours prior to event start time. However, external user testing revealed that users miscalculate the cutoff time when only shown the event start time. 

The system shall explicitly compute and store the **`cancellation_deadline`** ($T_{\text{event}} - 24\text{ hours}$) and display both the formatted cutoff datetime and remaining countdown duration on registration records and CLI receipts.

---

## 2. Affected Baseline Artifacts
* **SRS Requirement:** `FR-05` (Registration Cancellation), `FR-06` (Late Cancellation Rejection).
* **New Sub-Requirement:** `FR-05b` — The system shall display the exact cancellation cutoff datetime and status flag (`cancellation_allowed: true/false`) on all student ticket views.
* **User Stories:** `US-08` (Cancel Registration Before Deadline).
* **Test Case:** `CancellationPolicy_DisplaysExactCutoffTimestamp`.

---

## 3. Impact Assessment
* **Architecture / Data Model:** Minimal. `Registration` entity adds a helper method `GetCancellationCutoff() -> std::chrono::system_clock::time_point`.
* **Backlog Impact:** +1 Story Point to `US-08` (adjusted from 3 pts to 3 pts with amended criteria). MoSCoW remains **Must**. Total backlog points remain compliant with $\le 60\%$ rule.
* **Backward Compatibility:** 100% compatible with existing CLI and CSV schemas.

---

## 4. Decision
* **Decision:** **Approved by Project Team & Client Representative**.
* **Action:** Baseline updated to **SRS v1.1** (Git tag: `srs-v1.1`).
